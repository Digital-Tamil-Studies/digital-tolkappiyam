# Deploying to GitHub Pages

The site is plain static files in `app/` with relative paths, so it works as a
GitHub Pages project site (`https://<your-username>.github.io/<repo>/`) without
changes. The workflow in `.github/workflows/pages.yml` publishes only `app/`
on every push to `main`.

## What the browser needs

```
app/index.html
app/assets/app.js
app/assets/styles.css
app/data/thol.js      sutras + structure      (generated by scripts/build.py)
app/data/dict.js      dictionary + glosses    (generated by scripts/build.py)
app/data/notes.js     commentaries            (generated by scripts/build.py)
```

The generated files are committed, so the workflow has no build step.

The whole project is pushed, which keeps the scripts and data versioned too.
`.gitignore` already leaves out the two PDFs, the page renders
(`data/work/scan_1961/png/`, `data/work/png/`) and the Tesseract models
(`data/work/tessdata/*.traineddata`). The repository is about 35 MB.

## First deployment

1. Rebuild the data, since the site serves the generated files in `app/data/`:

   ```
   cd /home/natkeeran/dev/opencode_work/digital_thol
   python3 scripts/build.py
   ```

2. On github.com, create an empty public repository, e.g. `tholkappiyam`,
   without a README, licence or .gitignore.

3. Initialise git, commit and push:

   ```
   git init -b main
   git add .
   git status            # check that no PDFs, png renders or .traineddata are listed
   git commit -m "Tholkappiyam reader"
   git remote add origin git@github.com:<your-username>/tholkappiyam.git
   git push -u origin main
   ```

4. On GitHub, open **Settings → Pages**. Under **Build and deployment**, set
   **Source** to **GitHub Actions**.

5. Open the **Actions** tab. If the first run failed because Pages was not yet
   enabled, choose **Deploy to GitHub Pages → Run workflow**. After a minute
   the site is live at `https://<your-username>.github.io/tholkappiyam/`.

## Updating the site

```
python3 scripts/build.py
git add -A
git commit -m "Update"
git push
```

The workflow redeploys `app/` on every push to `main`.

## Testing locally before pushing

```
python3 scripts/serve.py          # http://localhost:8050/
```

## Before making it public: rights

- Project Madurai text: freely redistributable with its header page intact
  (kept in `data/source/pmuni0100.html`).
- 1961 commentary (புலியூர்க் கேசிகன் தெளிவுரை): the author died in 1985, so
  the work is likely still in copyright unless his works were nationalised.
- English translation (V. Murugan, *Tolkāppiyam in English*, Institute of
  Asian Studies, 2001): almost certainly in copyright.

Publishing only `app/` does not keep the rest private: in a public repository
anyone can browse `data/` on GitHub too.

To deploy without the commentaries, leave `app/data/notes.js` out: add it to
`.gitignore` and remove the `<script src="data/notes.js"></script>` line from
`app/index.html`. The site then works as before, and the poem view shows no
commentary panels. The transcribed sources should then also be kept out of a
public repository: `data/work/commentary_1961.csv`,
`data/manual/transcribed_1961/`, and the English and 1961 columns in
`data/final/tholkappiyam.csv`.
